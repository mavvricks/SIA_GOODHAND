# Deploying Goodhand on Vercel and Neon

The two apps use separate Neon PostgreSQL databases. Local SQLite files cannot serve a Vercel deployment. The migration scripts have already been applied to the two Neon databases configured on this machine; do not import SQLite again into a populated database.

1. In each Neon project, select branch **production**, database `neondb`, and role `neondb_owner`. Use **Connect → Postgres database → Connection pooling ON** for the app URL. Store and FSM must have different hosts/projects. Keep URLs secret. Migrations run from the repository root and load private `.env.local` files.
2. Run `pnpm db:migrate`, `pnpm db:cloud-status`, `node scripts/verify-postgres.mjs`, `pnpm test`, `node scripts/contract-check.mjs`, `pnpm build`, and `pnpm e2e` locally. The one-time import is already recorded in both databases.
3. Connect [the Goodhand GitHub repository](https://github.com/mavvricks/SIA_GOODHAND) to Vercel. Create **two projects** from it. Select `apps/store` as the Store Root Directory and `apps/fsm` as the FSM Root Directory. Select Next.js and Node.js 24. Enable **Include source files outside the Root Directory in the Build Step**, because both apps import `packages/`. Use the pnpm lockfile, `pnpm build` for each app package, and the default Next.js output directory.
4. Set Store Vercel variables: `STORE_DATABASE_URL`, `STORE_SESSION_SECRET`, `STORE_FSM_BASE_URL`, `STORE_SERVICE_CLIENT_ID`, `STORE_SERVICE_CLIENT_SECRET`, `STORE_WEBHOOK_SIGNING_SECRET`, `FSM_SESSION_SECRET`, `CRON_SECRET_STORE`, `STORE_PUBLIC_URL`, `INSTALLATION_INTEGRATION_ENABLED=true`, `DEMO_MODE=false`. Set `STORE_FSM_BASE_URL=https://<fsm-domain>/api/v1`. Copy the FSM session secret to Store so Store can verify scoped stock service tokens.
5. Set FSM Vercel variables: `FSM_DATABASE_URL`, `FSM_SESSION_SECRET`, `FSM_STORE_BASE_URL`, `STORE_SERVICE_CLIENT_ID`, `STORE_SERVICE_CLIENT_SECRET`, `STORE_WEBHOOK_SIGNING_SECRET`, `CRON_SECRET_FSM`, `FSM_PUBLIC_URL`, `DEMO_MODE=false`. Set `FSM_STORE_BASE_URL=https://<store-domain>/api/v1`. The service client ID/secret and webhook signing secret must match Store values. Store and FSM session secrets should be different; only the FSM secret is also copied to Store for token verification.
6. In GitHub repository **Settings → Secrets and variables → Actions**, add `STORE_PUBLIC_URL`, `FSM_PUBLIC_URL`, `CRON_SECRET_STORE`, and `CRON_SECRET_FSM`. `.github/workflows/drain.yml` calls both authenticated endpoints every five minutes. Trigger the workflow manually once and inspect both responses.
7. Deploy both Vercel projects, sign into each as an authorized account, make a test hardware-only order and an installation order, and check Store tracking, FSM Jobs Queue and both Operations pages. Test checkout, claim, completion, and signed callback with test data. Rotate known demo passwords before public access. Finish payment, email, and security reviews before real sales.

Keep connection strings and secrets out of Git. `.env.local` and `.data/` are ignored. Payment remains simulated. The hosted adapter serializes writes and loads current domain rows per request, so monitor Neon connections and request duration as traffic grows.

Neon [recommends pooled connections for serverless workloads](https://neon.com/docs/connect/connection-pooling). Vercel documents the [monorepo source setting](https://vercel.com/docs/monorepos/monorepo-faq). If a deployment fails after a schema change, restore a compatible app build and Neon branch snapshot together.
