# Project Context: SYSINT_GOODHAND (Group X-MEN, Section TB42)

## 1. Project Overview
Integration project for **Goodhand Security Products** connecting two independent systems[cite: 10, 58]:
- **System A (`apps/store`)**: Customer-facing E-Commerce Storefront (sales, payments, inventory ledger, warranty activation, outbox dispatcher)[cite: 6, 11, 13].
- **System B (`apps/fsm`)**: Field Service Management App (technician scheduling, dispatch, job execution, installation completion reports)[cite: 6, 11, 13].

## 2. Tech Stack & Codebase Rules
- **Stack**: `pnpm` workspace monorepo, TypeScript, Next.js App Router, Zod, OpenAPI 3.x (`packages/contract`)[cite: 6, 33].
- **Important**: Academic reference documents contain illustrative PHP/Laravel snippets[cite: 42, 44]; **DO NOT write PHP**. Keep all code strictly in TypeScript matching the existing monorepo architecture.
- **Design Pattern**: Separate published interface contracts (`packages/contract`) from service/adapter implementations (`lib/services`, `lib/outbox`, `lib/ledger`)[cite: 6, 43].

## 3. Mandatory Contract & Peer-Review Invariants (D-01 to D-13)
All code and tests must enforce the 13 accepted peer-review fixes[cite: 28, 30, 71]:
1. **Versioning (`D-06`)**: Explicit URI path versioning (`/api/v1/...`) across all endpoints[cite: 32, 34].
2. **Strict Schemas (`D-03`, `D-08`)**: OpenAPI 3.x + Zod validation at **both** System A and System B boundaries[cite: 33, 35]. Reject unknown fields (`strict()`), enforce length/numeric bounds, use RFC 3339 / ISO 8601 timestamps, strings for phone numbers, positive integers for quantities, and exact job statuses: `Pending Scheduling`, `Scheduled`, `In Progress`, `Completed`, `Cancelled`, `Reschedule Required`[cite: 13, 28, 33].
3. **Resilience & Outbox (`D-04`, `D-05`)**: Checkout must never block on System B. Use the asynchronous outbox (`apps/store/lib/outbox/outbox-engine.ts`) with explicit timeouts, bounded retries (max 3–5 attempts with exponential backoff), a dead-letter/failed queue, and idempotency keys (`reference_id`) so replays never duplicate jobs or double-deduct stock[cite: 6, 15, 28, 34].
4. **Security (`D-07`)**: OAuth 2.0 client credentials (`/api/oauth/token`) for Store-to-FSM calls, and signed/authenticated inbound webhooks to Store.
5. **Observability (`D-09`)**: Propagate a `correlation_id` across every request, queue message, webhook, and structured JSON log via `packages/logger`, masking PII[cite: 6, 28, 36].
6. **Performance & Availability (`D-10`, `D-11`)**: Target `<200ms` latency for non-file API calls and support graceful degradation/manual fallback when System B is offline[cite: 28, 37].
